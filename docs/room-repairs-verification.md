# 道路、梯子与中文提示修复

2026-09-07；Godot 4.7.2，Blender 5.2.1，Windows / RTX 3070，Forward+。

## 原因与修复

| 问题 | 原因 | 修复 |
|---|---|---|
| 人物、箱子穿过道路木柱 | 重复拱架无碰撞，两个柱脚沿行走方向摆在路内 | 拱架旋转横跨道路，柱脚移到两侧；结构碰撞按实际模型局部边界生成，中央路线不变 |
| 梯顶手抓空气 | 脚底可到 3.35 m，而模型最高踏档约 3.3 m；没有平台过渡 | 平台出口高度 3.23 m，梯子扶手 4.55 m、最高踏档 4.45 m；手部骨骼贴合真实踏档，带碰撞检测登上平台 |
| 原地、受阻时仍攀爬 | 动画始终循环，与实际位移无关 | 按实际攀爬位移推进动画，静止保持抓梯姿势；攀爬朝向对准梯子 |
| 提示中英混杂 | 新交互代码硬编码英文，并直接显示内部物品类型 | 所有交互说明改为中文；保险丝、齿轮、砝码、手轮有中文名称，未知类型显示“物品” |
| 手柄仍显示 W/S | 攀爬说明没有使用输入提示映射 | 增加纵向操作占位符，显示键盘 W/S、方向键或手柄摇杆／十字键上下；菜单键中文化 |
| 松梯后在空中起跳 | 梯子使用 move_and_collide，残留上梯前的着地状态 | 离梯首帧清除跳跃缓冲和离地宽限，重新计算落地；跳跃键在梯上只用于松手 |
| 从梯顶上方抓梯突然下移 | 接入未校验脚底高度，随后被攀爬范围钳制 | 拒绝范围外接入；同时检查站姿空间，防止蹲伏状态抓梯后穿过低顶 |
| 平台被挡住时悬停 | 登出缺少受阻与撤回处理 | 整段移动检查碰撞；堵塞时可向下退回梯子，或主动松手，途中新增障碍也可撤回 |
| 前景柱遮住主角 | 挪至道路侧面的柱子位于电影镜头前景 | 靠近主角时前景结构平滑淡出，碰撞不变，离开后恢复 |

## 验证

- `test_room_repairs.gd` 检查角色／箱子碰撞、中央通道、前景淡出、手部踏档接触、登顶与下梯、受阻撤回、暂停、松手、低顶、重生，以及四章所有房间的中文交互提示。
- `test_full_routes.gd` 改为复用现有输入适配器；默认仍使用动作输入，增加 `-- --controller` 可通过原始 Xbox 事件验证同一条路线，不跳过谜题、不传送角色。
- 键盘与 Xbox 脚本输入均完成四章 24 个房间。新增专项纳入 Windows 与 macOS 验证器。
- 最终 Windows 验证器全部 26 套、537 项检查通过；其中新增专项 41 项检查。最终日志为 `artifacts/room-repairs-final-verification.log`。
- 窗口截图位于 `artifacts/repair-*.png`：四章正常游戏镜头下的道路、梯子底部／中段／顶部及登出后的平台。新增手部贴合后再次检查了梯顶画面。
- 梯子源文件与模型在隔离副本生成；Blender 重新导入、UV、相对纹理路径和共享贴图哈希检查通过。生成器支持 `--only ladder`，无需重建其他素材。
- Windows Release 在隔离工程完成导出、PE/PCK 与打包校验，复制至独立目录后启动 120 帧，退出 0。交付 `build/MidnightWorkshop.exe` 与 `build/MidnightWorkshop-Windows.zip`；ZIP 的 CRC、五个条目和内外 EXE SHA-256 一致，校验数据见 `artifacts/room-repairs-release.json`。

对比截图：`artifacts/repair-before-arch.png` / `repair-workshop-arch.png`，`repair-before-ladder-top.png` / `repair-ladder-top.png`。修改前截图使用提交 `3e98215` 的运行脚本和梯子模型，在隔离工程中重现；修改后额外包含键盘和手柄中文提示截图。

手柄验证使用注入的原始 Xbox 按钮事件，没有连接实体手柄人工试玩。脚本测试与截图证明上述修复，不代表穷尽所有可能的关卡问题。当前已有 `.import` 改动保持独立，不纳入修复提交。
